日期：2026-10-31。基线对应原提交 `229de311a1190db9a28de1bc1cbf2956d222557c`。先运行原有测试与 30 题，再修改上传、安全和异常处理。本记录属于后续 RAG 升级之前的验收点。

## 1. 实际完成了什么

### 上传限制

- 网页框架最大单文件由 2 MiB 改为 12 MiB；框架入口放行后，应用按类型校验。
- TXT/Markdown 每份最多 512 KiB；图片每份 8 MiB；PDF/DOCX 每份 12 MiB。
- 原始上传最多 10 份、总计 24 MiB；在 OCR、PDF 渲染之前检查。
- 提取后的文字每份最多 512 KiB、总计 2 MiB；超出时提示拆分原文档。原文件容量与文字容量是两种不同限制，页面均已说明。
- 限制统一由 `studylens/limits.py` 对外提供；后续 API 与网页可以调用同一套检查。

### 模型接口出口

- 默认允许 `https://api.deepseek.com`、`https://api.openai.com/v1`、`https://api.siliconflow.cn/v1`。
- 用户填写的地址必须完整匹配部署者审核过的基址。IP、localhost 类域名、凭据、端口、URL 转义、额外路径及查询参数均不允许。
- 部署者可用 `STUDYLENS_ALLOWED_MODEL_BASE_URLS` 追加逗号分隔的完整基址；浏览器中的用户不能改变这个列表。
- HTTP 请求继续禁止重定向，不自动重试，不向界面回显服务商原始错误或密钥。
- 这是一套服务商白名单边界，不声称解决被信任域名本身遭篡改等所有网络攻击。部署者追加域名时必须确认其真实归属和网络出口。

### 异常与资源边界

- 导入新资料先构建完整索引，成功才替换会话状态。有效文件 A → 坏文件 B → 换回 A 不再触发 `KeyError`。
- PDF 每页提取失败都会记录警告。OCR 失败时保留已有短文字；真正缺失的页明确列出。界面显示“总页数 / 已提取页数”，避免部分导入显示为全量成功。
- PDF 在位图分配前检查渲染尺寸，限制 2000 万像素，及时关闭渲染资源；逐页处理之间检查 90 秒文档处理预算。
- OCR 统一使用 Tesseract，并对单次识别设置 20 秒超时。不再依赖旧环境恰好安装的 RapidOCR。
- 损坏 DOCX 的 XML 异常、模型服务返回错误结构，都转成明确的用户错误。
- 开发容器恢复 CORS/XSRF 默认保护，取消无关系统全量升级及重复安装 Streamlit。

## 3. 30 题基线及失败分析

产物：`evaluation/baseline_2026-10-31.csv`、`evaluation/baseline_2026-10-31.json`。JSON 包含配置、题集与语料 SHA-256、各项计数、失败案例；CSV 保留每题召回片段和分数。

参数：字符 TF-IDF，`top_k=3`，`min_score=0.08`；三份教学笔记，15 道单段、10 道多段、5 道无答案问题。

- 单段证据命中：15/15，100%。
- 多段全部证据覆盖：10/10，100%。
- 无答案问题空检索：0/5，0%。
- 模型回答正确率、引用语义支持率、模型拒答正确率：**未测试**，JSON 值为 `null`，不能把上述检索指标当作答案准确率。

五个失败案例都属于“资料没有答案，却检索到了相关字词”：

1. Q26 问期末考试日期，召回课程学习笔记标题，但没有日期。
2. Q27 问 Polar 在 2 dB 的 FER，召回性能记录说明，但没有实验数值。
3. Q28 问列表 32 相比 SC 的 dB 提升，召回 SCL/SC/CRC 说明，但没有比较结果。
4. Q29 问老师邮箱，召回课程笔记与复习卡片，但没有邮箱。
5. Q30 问神经网络学习率，召回学习周期等字词相似段落，但没有训练配置。

因此主要问题是“字面相关不等于证据充分”。后续改进应分别检验检索覆盖、重排噪声过滤、缺失事实拒答，并增加同义表达、歧义、版本更新和真实业务题。自带题集是开发集，不能当成独立盲测集。升级前后比较时应保留同一题集，同时单独增加未参与调参的验收题。

## 4. 自动化检查

`.github/workflows/ci.yml` 在推送 main、PR 或手动触发时运行：

1. Python 3.10 和 3.11 安装声明的基础依赖。
2. 依赖一致性检查和三组基础回归测试。
3. 执行 30 题检索，比较基线；题集、语料、配置变化必须明确更新基线，证据覆盖回退会失败。
4. 上传本次 CSV/JSON，便于查看失败题。

CI 中无答案空检索的旧基线仍是 0/5；自动化通过仅表示没有比旧基线更差，不代表这个问题已被解决。GitHub 远程运行状态以实际 Actions 结果为准。

## 5. 回滚方式

基础修复已保存为独立提交 `d687708`（`fix: enforce upload and provider limits and establish tested baseline`），后续 RAG 升级使用后续提交。之后还补充了空端口 URL 校验、全 PDF 提取失败提示和基线文件防覆盖检查；这些补充归入后续提交。先在本地测试回滚结果，再推送；不要强制推送覆盖别人提交。

```powershell
git log --oneline -8
# 将下面占位符替换为需要撤销的那一次提交，不要原样输入尖括号。
git revert <需要撤销的提交ID>
git push origin main
```

若撤销的是 RAG 升级，应保留基础安全修复。若不得不撤销基础安全修复，则应同时暂停公开模型接口或上传入口，避免已知风险重新开放。`git revert` 保留历史、生成反向提交；不是删除整个仓库。
